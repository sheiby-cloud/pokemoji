# ポケもじ

カタカナで書かれたポケモンの名前を、1文字ごとの色ヒントを頼りに当てる非公式ファンメイドの文字当てゲームです。
問題はプレイヤーごとにランダムに出題され、何問でも続けて遊べます。

## 遊び方

- 正解の文字数はマス目で分かります。決められた回数(初期値は6回)以内に当ててください
- 入力できるのは実在するポケモン名で、正解と同じ文字数のものだけです。ひらがな・半角カタカナ・全角英数でも入力できます
- 緑: 位置も一致 / 黄: 含まれるが位置が違う / 灰: 含まれない(正解に含まれる個数分だけ色がつきます)
- 小さい文字・濁点・半濁点・長音「ー」・記号はそれぞれ独立した1文字です(「カ」と「ガ」は別)
- 設定で難易度を調整できます
  - 出題範囲: 第1世代まで 〜 第9世代まで(初期値: 第9世代まで)
  - 回答できる回数: 5〜12回(初期値: 6回)
  - 入力候補を表示する: オン/オフ(初期値: オン)
  - 出題範囲と回数は、解いている途中に変えると次の問題から適用されます(まだ1回も入力していなければすぐ適用)

## 毎日の連続達成

- 1日に1問以上正解すると、その日を「達成」として数えます(日付の区切りは端末の時計の0時)
- 正解しない日があると連続日数は0に戻ります。間違えても、その日のうちに正解すれば途切れません
- ヘッダーの 🔥 に連続日数を表示します。今日まだ正解していないときは薄く表示します
- 成績画面に「連続達成日数」「最長連続日数」「今日の正解数」を表示します
- 記録はブラウザの localStorage に保存されるため、端末やブラウザごとに別々に数えられます
- 判定の処理は `logic.js` の `recordDailyWin` と `dailyStatus` です

## 設定項目を追加・変更する

設定はすべて `main.js` の先頭にある `SETTINGS` 配列で定義しています。項目を1つ追加すれば、設定画面のボタン・スイッチ、保存、初期値、不正な保存値の読み直しが自動で行われます。

```js
{
  key: 'maxTries',            // settings.maxTries で参照する保存名
  group: '難易度',             // 設定画面の見出し
  label: '回答できる回数',
  type: 'choice',             // 'choice'(ボタンから1つ選ぶ) か 'toggle'(オン・オフ)
  options: range(5, 12),      // choice の選択肢
  default: 6,
  perGame: true,              // 問題の開始時に固定し、途中で変えたら次の問題から適用
  note: (v) => `${v}回まで回答できます`,
  onChange: (v) => { /* 変更時に必要な処理 */ },
}
```

- 選択肢や初期値を変える: `options` / `default` を書き換える(保存済みの値が選択肢から外れた場合は初期値に戻ります)
- 回数の上限を12回より増やす: `MAX_TRIES_LIMIT` も合わせて変える
- 設定値をゲームで使う: `settings.<key>`(`perGame: true` の項目は `game.<key>`)を参照する

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| index.html | ページ本体 |
| style.css | 見た目 |
| logic.js | 判定・正規化・50音表の並びなどの純粋関数(ブラウザと Node.js で共用) |
| main.js | ゲーム進行、入力、保存 |
| names.json | 出題・入力判定に使う名前リスト(5文字以下のみ) |
| favicon.svg | オリジナルのファビコン |
| scripts/build-names.js | names.json を生成するスクリプト(公開対象外) |
| scripts/serve.js | ローカル確認用サーバー(公開対象外) |
| tests/ | 判定ロジックのテスト(公開対象外) |
| _config.yml | GitHub Pages で `scripts/` `tests/` などを公開しない設定 |

外部サービスへの通信、画像、広告、アクセス解析は含みません。保存はブラウザの localStorage のみです。

## ローカルで動かす

Node.js 18 以上が必要です。`names.json` を fetch で読み込むため、ファイルを直接開かずにサーバー経由で開いてください。

```bash
node scripts/serve.js
```

http://localhost:8000/ を開きます。

## テスト

```bash
node --test tests/
```

仕様書5章のテストケース(ライチュウ/ピカチュウ、ガラガラ/カラカラ など)、正規化、入力チェック、names.json の形式を確認します。

## GitHub Pages で公開する

1. GitHub に新しいリポジトリを作り、このフォルダの中身を main ブランチに push する
2. リポジトリの Settings → Pages を開く
3. Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして Save
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開される

`_config.yml` の `exclude` により、`scripts/` `tests/` `README.md` `package.json` は公開されません。

フッターの連絡先は X の @sheiby_co_ltd です(`index.html` の `id="contact"` のリンク)。変える場合はここを書き換えてください。

## 新しいポケモンが追加されたときの names.json の更新手順

データ元は [PokéAPI](https://pokeapi.co/) のポケモン種族データ(日本語カタカナ名 `ja-Hrkt` と初登場世代)です。

1. PokéAPI に新しいポケモンが反映されていることを確認する
2. 生成スクリプトを実行する(約1000件を取得するので1〜2分かかります)

   ```bash
   node scripts/build-names.js
   ```

3. 出力される確認用レポートを目で見て確認する
   - 世代ごとの件数(5文字以下 / 全体)
   - 記号・数字・英字を含む名前の表記(ニドラン♀、ニドラン♂、ポリゴン2、ポリゴンZ など)
   - 日本語名や世代が取得できなかった種族の警告
   - 第10世代以降のデータがあれば警告が出ます(テストも失敗します)。その場合は `main.js` の世代ボタンと範囲チェック(1〜9)、`tests/logic.test.js` の世代チェックを広げてください
4. テストを実行して通ることを確認する

   ```bash
   node --test tests/
   ```

5. `names.json` をコミットして push する

名前は Unicode 正規化(NFKC)してから保存しています。6文字以上の名前(タイプ:ヌル、カプ・コケコ など)は出題・入力の対象外です。
